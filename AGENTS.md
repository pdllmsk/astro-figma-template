# AGENTS.md — правила проекта

Лендинг на Astro 5 + Tailwind CSS 4 по макету Figma: мобильная, планшетная и десктопная версии, много анимаций. Вёрстка сразу готова к переезду контента в CMS (см. «Задел под CMS»).
Эти правила обязательны при добавлении и изменении кода. Если задача не укладывается в правило — остановиться и спросить, а не придумывать новую структуру.

pnpm-монорепо: `frontend/` — Astro-лендинг (`@repo/frontend`). CMS, когда понадобится, встаёт рядом отдельным пакетом. Все пути `src/…` ниже — внутри `frontend/`. Переменные окружения — один `.env` в корне (пример — `.env.example`).

Состояние проекта — в `.ca-workflow/workflow.md`: Figma-файл, фреймы, брейкпоинты, токены, шрифты, таблица блоков. Читать перед любой работой с макетом и обновлять по ходу.

## Команды

Из корня репозитория:

- `pnpm start` — дев-сервер
- `pnpm prettier` — форматирование (сортирует Tailwind-классы)
- `pnpm check` — проверка типов (`astro check`)
- `pnpm build` — прод-сборка: node standalone для Docker (`Dockerfile`)
- `pnpm build:static` — статический сайт в `frontend/dist` без сервера. Серверных эндпоинтов (приём форм) в статике нет

Перед завершением любой задачи: `pnpm prettier && pnpm check && pnpm build` без ошибок.

## Старт проекта

Делается один раз, до первого блока. Пока токены — заглушка (`tokens.css`, `typography.css`, `TextVariant.ts`, `SPACE`), блоки не верстаются.

1. Пользователь даёт ссылки на фреймы макета: от одного до трёх, по одному на размер экрана. Записать в `workflow.md`: ключ файла, фреймы (название, node, ширина). В таблицу блоков добавить колонку `node (<ширина>)` на каждый фрейм — на все, включая те, что не получили свой уровень пропов.
2. Из фреймов (`get_variable_defs`, `get_design_context`, `get_metadata`) достать:
   - цвета (Figma Variables) → `--color-*` в `tokens.css`, строки в `colors` в `ui/Text/Text.astro`, цвета `ui/Buttons/BtnBase`;
   - текстовые стили → `--text-*` и `--tracking-*` в `tokens.css`, `@utility typo-*` в `typography.css`, строки в `ui/Text/TextVariant.ts`. Если стиль на разных фреймах разный — отдельные токены с суффиксом `-tab` / `-mob`;
   - отступы (insets/spacing) → `SPACE` в `constants/space.ts`; отступ секции, ширины колонок → `--spacing-section`, `--container-*`, `ui/Section`, `ui/Content`;
   - тени, радиусы, обводки — если есть в переменных.
     У каждого токена — комментарий, откуда он (переменная Figma или блок). Заглушки удалить.
3. Брейкпоинты. Ширина фрейма — база масштаба, но не всегда граница диапазона (широкий десктоп обычно включается раньше своей ширины). Предложить пользователю границы, после подтверждения записать в `workflow.md` и синхронно в три места: `--breakpoint-*` в `tokens.css`, уровни масштаба в `styles/global.css`, `constants/breakpoints.ts`. Код рассчитан на уровни `base` / `tab` / `desk`: фреймов меньше — лишние уровни масштаба убрать из `global.css`, пропы передавать одним значением; фреймов больше трёх — остановиться и спросить.
4. Шрифты: выписать из текстовых стилей. Есть в Google Fonts — `fontProviders.google()` в `experimental.fonts` (`astro.config.mjs`); нет — попросить у пользователя файлы в `src/assets/fonts/` и подключить через `fontProviders.local()`. В `components/Head` — `<Font cssVariable="…" preload />` на каждый, в `tokens.css` — `--font-*`. Отметить в `workflow.md`, откуда каждый шрифт и какого не хватает.
5. Проверка: витрина `/test/preview` показывает все текстовые стили и цвета, `pnpm check` без ошибок. В `workflow.md` — статус токенов и дата.

## Задел под CMS

Контент со временем переезжает в CMS, поэтому блок с первого дня не знает, откуда пришли данные:

- Блок получает всё через `Props` (`export interface Props`), контент лежит в `data/*.data.ts` блока и типизирован этими `Props`. Страница импортирует data-файл и передаёт его блоку. При переезде меняется только источник на странице, сами блоки не трогаются.
- В разметке блока нет текстов, ссылок, списков и контентных картинок — только в `data/`. Оформление по макету (цвета карточек, кадрирование, декор, иконки) может жить в `data/` рядом с контентом, но отдельными полями, не внутри текста.
- Тексты — без HTML. Переносы — маркеры: Enter — везде, `[desk]` — только десктоп, `[tab]` — только планшет, `[mob]` — только мобилка, `{текст}` — ссылка. В HTML их собирает `utils/lines.ts` без типографа: неразрывные пробелы — символ U+00A0 в тексте, расставлены по макету.
- Поля `Props` — простые: строки, числа, массивы объектов, картинки. Никаких функций и разметки в данных.

## Структура фронта (frontend/)

```
src/
  pages/            роуты; страница только собирает блоки, своей вёрстки не содержит
    test/preview    витрина ui-компонентов
  layouts/          PageLayout: <html>, Head, <main>
  components/       блоки лендинга (секции страницы) и их части; Head — <head> страницы
  ui/               переиспользуемые примитивы, не знающие о конкретном блоке
  styles/
    tokens.css      все дизайн-токены (@theme) — единственный источник
    typography.css  текстовые стили макета как утилиты typo-*
    global.css      подключение Tailwind, масштабирование, base-стили
  constants/        константы: breakpoints.ts (синхронизирован с global.css), space.ts (шкала отступов Figma)
  utils/            чистые функции и хелперы без вёрстки; responsive.ts — адаптивные пропы, lines.ts — маркеры переносов
  test/             витрина UiPreview и общие тестовые хелперы
  types.ts          общие типы (DataAttrs, SVG, Tag)
public/             файлы, которые отдаются как есть (favicon, og)
```

Алиасы: `@components/*`, `@ui/*`, `@layouts/*`, `@utils/*`, `@constants/*`, `@test/*`. Относительные импорты — только внутри своей папки компонента.

## Блоки (components/)

Каждый фрейм секции в Figma = один компонент в `components/`. Страница `pages/index.astro` перечисляет блоки по порядку и передаёт им данные из `data/`.

Пользователь даёт ноды блока — по одной на каждый фрейм из `workflow.md`. Сначала записать строку в таблицу блоков `workflow.md` (имя компонента, node на каждый фрейм), потом верстать. Новый блок в макете → новая строка в таблице и новая папка. Не дописывать чужой блок, чтобы «влез» новый.

Автономный режим: таблица заполнена заранее — пройти строки, для которых ещё нет папки `components/<Имя>/`, по одной: вёрстка → `pixel-check` → следующая.

### Анатомия компонента

```
components/Hero/
  Hero.astro            разметка блока; экспортирует interface Props
  Hero.ts               клиентский скрипт (анимации, интерактив), если нужен
  Hero.types.ts         типы данных, если их больше, чем помещается в Props
  parts/
    HeroTitle/
      HeroTitle.astro
    HeroCrest/
      HeroCrest.astro
      HeroCrest.ts
      assets/crest.svg
  data/
    hero.data.ts        контент блока (тексты, списки, ссылки), типизирован через Props
    assets/             контентные картинки (фото, иллюстрации)
  assets/               декор и иконки, принадлежащие только этому блоку
```

Правила:

- Имена — PascalCase. Часть блока называется с префиксом родителя: `HeroTitle`, `MenuCard`, `FaqItem`.
- Папка = компонент; файл называется как папка. Один `.astro` на папку (исключение — адаптивные пары, см. ниже).
- Вложенность `parts/` — не глубже двух уровней (`Block/parts/BlockPart/parts/BlockPartItem`). Глубже — значит часть пора поднять в `ui/` или упростить.
- Контент — в `data/*.data.ts`, а не в разметке (см. «Задел под CMS»).
- `Props` всегда экспортируется (`export interface Props`), чтобы страница и родитель типизировали данные.

### Куда класть: parts, ui или общий компонент

| Ситуация                                                                                                                                           | Место                                                              |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Элемент нужен только одному блоку                                                                                                                  | `components/<Block>/parts/`                                        |
| Элемент из Figma-раздела компонентов (кнопки, иконки, поля форм) или встречается в 2+ блоках, не зависит от их контента                            | `ui/`                                                              |
| Составной фрагмент с контентом, повторяющийся в 2+ блоках (например, карточка отзыва в двух секциях)                                               | `components/<Shared>/` с собственной папкой, блоки импортируют его |
| Повтор внутри одного блока                                                                                                                         | `parts/` + `.map()` по данным, не копипаст                         |

Если часть одного блока начинают использовать во втором — переносить её в `ui/` или общий компонент сразу, а не импортировать из чужих `parts/`. Импорт из `components/X/parts/` разрешён только внутри `components/X/`.

### Расширение и варианты

- Отличия одного компонента в разных местах — через проп `variant` и объект вариантов (`const variants = { ... } as const`), как в `ui/Section`, `ui/Buttons/BtnBase`. Не копировать компонент ради другого цвета или отступа.
- Внешние отступы задаёт родитель через проп `class`; компонент управляет только собственными внутренними стилями. Каждый компонент принимает `class` и ставит его последним в `class:list`.
- Новые возможности добавляются опциональными пропами с дефолтом, чтобы не ломать существующие вызовы.

## ui/

Примитивы: `Section` (секция с отступами), `Content` (контентная колонка: ширины — токены `--container-*`, `variant="wide"` — во всю ширину до десктопа), `Stack`, `Text`, `Link`, `Buttons/BtnBase`, `MyImage`, `MyPicture`. Ui-компонент не импортирует ничего из `components/` и не содержит контента.

### Stack и Text — основа вёрстки блока

Внутри блоков раскладка собирается из `Stack`, текст — из `Text`. Их пропы повторяют Figma: auto-layout переносится в `Stack`, Text Style — в `variant`.

```astro
<Stack
  as="header"
  direction={{ base: "column", desk: "row" }}
  gap={{ base: 24, desk: 80 }}
  align="center"
  justify="between"
  py={{ desk: 144 }}
>
  <Text as="h2" variant={{ base: "heading-s", desk: "heading-xl" }} color="accent"
    >…</Text
  >
  <Text variant="body-l" align={{ desk: "center" }}>…</Text>
</Stack>
```

- Адаптивный проп (`Responsive<T>` из `@utils/responsive`) — одно значение или `{ base, tab, desk }`. `base` — мобилка, `tab` — с границы планшета, `desk` — с границы десктопа (границы — в `workflow.md`); незаданный `tab` берёт `base`, незаданный `desk` — `tab` (или `base`).
- `Stack`: `as`, `direction` (по умолчанию `column`), `align`, `justify`, `wrap`, `gap`, `p`/`px`/`py`/`pt`/`pr`/`pb`/`pl`. Отступы — px из шкалы `constants/space.ts` (значения Figma insets). Значения нет в шкале, но оно есть в макете — добавить в `SPACE`, а не обходить через класс.
- `Text`: `as` (тег по смыслу: `h1`–`h6`, `p`, `span`, `li`…), `variant` (обязателен), `color` (токены), `align`, `whiteSpace`, `html` (для `set:html`). Тег и стиль независимы: `<Text as="h2" variant="label-m">` — нормально.
- Новый текстовый стиль: токен `--text-*` в `tokens.css` → `@utility typo-*` в `typography.css` → строка в `ui/Text/TextVariant.ts`. Новый цвет текста — токен + строка в `colors` в `Text.astro`.
- Классы Tailwind на `Stack`/`Text` (через `class`) — только для того, что пропы не покрывают: размеры, позиционирование, фон, рамки, `grow`, порядок. Не дублировать пропы классами (`gap-6`, `flex-row`, `text-*` цвета на Stack/Text запрещены).
- Голые `<div class="flex …">` и `<p class="…">` в блоках не писать — брать `Stack` и `Text`. Исключение — декоративные элементы без раскладки и текста (слои, маски, линии).
- Новый вариант в ui-примитиве: литеральная тройка классов `["x", "tab:x", "desk:x"]` в его таблице. Классы не собирать шаблонными строками — Tailwind их не увидит.

Каждый новый ui-компонент добавляется в `src/test/UiPreview.astro` (страница `/test/preview`) со всеми вариантами. Моки для превью — в `ui/<Name>/test/`.

## Стили

Двухуровневая схема: **Tailwind-классы** + **scoped `<style>`** в том же `.astro`. SCSS, CSS-модули, inline `style=""` со статикой и отдельные `.css` для компонентов не использовать.

### Tailwind-классы — по умолчанию

Раскладка, отступы, размеры, типографика, цвета, простые `hover:`/`focus:` состояния.

- Только токены из `styles/tokens.css`. Произвольные цвета (`bg-[#123456]`) запрещены: нет нужного цвета — добавить токен.
- Отступы и размеры — шкалой spacing: класс = px макета / 4 (`p-6` = 24px, `gap-12` = 48px, `py-section` — токен отступа секции).
- Разовый размер, которого нет в шкале — arbitrary в px как в макете (`w-[328px]`). Сборка сама переведёт px в rem (`postcss.config.mjs`). Вручную rem и vw для размеров не писать.
- Текст — только через `<Text variant="...">` из `ui/Text`, флекс-раскладка — через `<Stack>` (см. раздел ui/).
- Длинные повторяющиеся наборы классов выносить в объект вариантов или в ui-компонент, не в `@apply`.

### Scoped `<style>` — для сложного

`@keyframes`, многоступенчатые переходы, `::before`/`::after`, декоративные слои, маски, градиенты, `clip-path`, scroll-driven анимации, стили контента из `set:html`.

```astro
<style>
  @reference "../../styles/global.css"; /* путь относительно файла */

  .crest {
    color: var(--color-accent);
    padding: --spacing(6);
    animation: shine 3s infinite;

    &::after {
      content: "";
      @apply bg-accent;
    }

    @variant desk {
      padding: --spacing(12);
    }
  }

  @keyframes shine {
    /* ... */
  }
</style>
```

- Цвета, шрифты и текстовые стили — только через токены: `var(--color-*)`, `var(--text-*)`, `var(--font-*)`; голые hex запрещены. Размеры — шкалой `--spacing(n)` или px из макета.
- Брейкпоинт — `@variant tab { }` / `@variant desk { }`, не `@media` руками.
- Классы в `<style>` — короткие семантические имена в рамках компонента (`.crest`, `.glow`); стили scoped, конфликтов нет.

## Мобилка и десктоп

- Mobile-first: базовые классы — мобилка, `tab:` — планшет, `desk:` — десктоп. Только планшет — `tab:max-desk:`; всё до десктопа — `max-desk:`.
- Масштабирование: px из кода при сборке становятся rem, а корневой `font-size` = 16px ровно на ширине фрейма макета. Каждый диапазон масштабируется от своего фрейма, самый широкий — без верхней границы (`styles/global.css`, числа — в `workflow.md`). Поэтому вёрстка в px макета тянется пропорционально экрану без медиазапросов на каждый размер. Нельзя: `vw`/`rem` для размеров руками и `font-size` на `html`.
- Одна разметка на все версии, если структура совпадает. Если структура принципиально другая — отдельные части `parts/<Block>Mobile` / `parts/<Block>Tablet` / `parts/<Block>Desktop`, скрытые классами брейкпоинтов, общие данные из одного `data`.
- Разные стили, отступы и направление — адаптивные пропы `{ base, tab, desk }` у `Text` и `Stack`, а не два элемента с `desk:hidden`.
- Картинки — `MyImage` с `imageDeskWidth` (px на десктопном фрейме), `imageTabWidth` (px на планшетном) и `imageMobWidth` (px на мобильном); разные кадры — `MyPicture` (`tabImage` / `tabImageWidth` для планшета).
- Значения для фрейма, которых нет в макете, помечать `// TODO: mob` (`tab`, `desk`) и не выдумывать.

## Анимации и скрипты

- Клиентская логика блока — в `<Name>.ts` рядом с компонентом, подключается из `.astro` через `<script>` и запускается через `componentInit` (`@utils/componentInit`), так как включён `ClientRouter`.
- Хуки для JS — `data-*` атрибуты (`data-hero-crest`, `data-animate="fade"`), не Tailwind-классы и не id.
- Скрипт ищет элементы внутри своего корня (`root.querySelectorAll`), а не по всему документу — блок должен работать, если на странице два экземпляра.
- Уважать `prefers-reduced-motion`: `motion-safe:` в классах, `@media (prefers-reduced-motion: reduce)` в `<style>`, проверка в JS.
- Повторяющиеся анимационные паттерны (появление по скроллу, параллакс) — один хелпер в `utils/`, а не копия в каждом блоке.
- Интерактив, включая формы, — `.astro` + `.ts`. React (`@astrojs/react`, классы через `classnames`) — только если нужен сложный state (календарь, многошаговая форма с валидацией) и по согласованию.
- Новые npm-зависимости (GSAP, слайдеры и т. п.) — только по согласованию.

## Изображения и иконки

- Растровые картинки из Figma — в `assets/` или `data/assets/` компонента, вывод через `MyImage` / `MyPicture`. Не класть в `public/`.
- SVG-иконки импортируются как компоненты (`import Icon from "./assets/icon.svg"`), цвет — через `currentColor` и класс `text-*`.
- Общие иконки (мессенджеры, телефон, стрелки) — в `ui/Icons/`.

## Работа с Figma

- Файл, фреймы и ноды блоков — в `.ca-workflow/workflow.md`.
- Для блока: `get_design_context` по каждой его ноде + скриншот. Сгенерированный код — референс: auto-layout переложить на `Stack`, текстовые стили — на `Text variant`, остальное — на токены и правила выше, не вставлять как есть.
- Перед вёрсткой сверить, что все цвета и текстовые стили блока есть в `tokens.css`; если нет — сначала добавить токен.
- После вёрстки или правки блока — скилл `pixel-check` (`.claude/skills/pixel-check/SKILL.md`) на каждом фрейме блока. Блок не готов, пока сверка не пройдена.

## Запрещено

- Стили вне Tailwind-классов и scoped `<style>`; ручные rem/vw в размерах; цвета и шрифты мимо токенов.
- Флекс-раскладка и текст мимо `Stack` и `Text`; отступы вне шкалы `SPACE`.
- Контент, захардкоженный в разметке блока, вместо `data/`; HTML в текстах вместо маркеров.
- Импорт из `parts/` другого блока; копипаст компонента ради варианта.
- Вёрстка прямо в `pages/`.
- Вёрстка блоков до старта проекта (пока токены — заглушка).
- Новые верхнеуровневые папки в `src/` без согласования.
